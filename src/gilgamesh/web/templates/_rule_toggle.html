{#- One rule's enable/disable control. This fragment is served twice: inside the full Rules page, and (when the request carries the `HX-Request` header) on its own as the response to an htmx POST. Keeping one renderer for both is what stops the live toggle and the no-JavaScript fallback from drifting apart. The plain form still works with JavaScript disabled: `action`/`method` post and the route answers with the whole page. With htmx loaded, the same POST is swapped in place (`hx-swap="outerHTML"`) — and because the swapped markup carries the same htmx attributes, the *next* click is live too. -#}
